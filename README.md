# ИрискИ — Frontend

Frontend веб-приложения **«ИрискИ»** для оценки финансовых рисков сделок с облигациями. Пользователь может указать параметры сделки, получить информацию об инструменте и просмотреть результат расчёта риск-метрики DV01.

## Технологии

- **React** — построение пользовательского интерфейса.
- **TypeScript** — типизация данных и компонентов.
- **Vite** — запуск и сборка приложения.
- **CSS** — стилизация интерфейса и адаптивная вёрстка.
- **Vitest** — модульное тестирование.
- **React Testing Library** — тестирование React-компонентов.
- **jsdom** — браузерное окружение для тестов.
- **ESLint** — статическая проверка кода.
- **Prettier** — форматирование кода.

## Запуск проекта

Требуются Node.js и npm.

```bash
npm install
npm run dev
```

### Режим демонстрационных данных

Для разработки интерфейса без запущенного backend можно создать файл `.env.local` в корне проекта:

```env
VITE_USE_MOCK_API=true
```

В этом режиме используются демонстрационные облигации и расчёт по их тестовым данным. Результат зависит от направления и количества бумаг.

Для работы с backend:

```env
VITE_USE_MOCK_API=false
```

Базовый путь API по умолчанию — `/api/v1`. При необходимости его можно переопределить через `VITE_API_BASE_URL`.

## Основная функциональность

### Реализовано

- Форма параметров одиночной сделки: ISIN облигации, направление покупки/продажи и количество.
- Валидация ISIN, включая проверку контрольной цифры.
- Проверка положительного целого количества облигаций.
- Сегментированный переключатель направления сделки и поле количества с кнопками увеличения и уменьшения.
- Получение информации об облигации через API или mock-данные.
- Отображение характеристик инструмента и доступных рыночных данных.
- Отправка запроса на расчёт риска.
- Отображение итоговой DV01 в рублях.
- Обработка состояний загрузки, успешного ответа и ошибок.
- Сброс устаревшего результата при изменении параметров сделки.
- Адаптивная вёрстка с плавным изменением пропорций карточек формы и результата.
- Корзина нескольких сделок: добавление с главной страницы и из корзины, редактирование направления и количества, удаление с возможностью вернуть позицию в течение 5 секунд.
- Запрет повторного ISIN в корзине независимо от направления сделки.
- Сохранение корзины, карточек и последнего результата в `sessionStorage` при перезагрузке вкладки.
- Перед расчётом обновляются данные всех бумаг; готовые позиции рассчитываются одним запросом с результатом в рублях и явным указанием количества включённых в итог позиций. Для остальных показывается причина исключения.
- Защита от запоздавшего ответа расчёта после изменения корзины.
- Запрос объяснения по ID расчёта на главной странице и в корзине: загрузка, проверенный ответ, источники фактов, ошибка и повторный запрос. Полученное объяснение сохраняется в текущей вкладке.

### Интеграция с backend

HTTP-клиент использует `credentials: 'include'` для поддержки сессионных cookie.

Расчёт риска выполняется запросом:

```http
POST /api/v1/risk-calculations
```

Параметры передаются в массиве `positions`, включая расчёт одиночной сделки:

```json
{
  "positions": [
    {
      "isin": "RU000A100006",
      "side": "buy",
      "quantity": 10
    }
  ],
  "incomplete": false
}
```

`incomplete` передаётся в исходном расчёте: `true`, если после обновления данных часть позиций корзины исключена; `false` для полной корзины и одиночной сделки. Backend сохраняет признак для объяснения. Ответ может содержать тот же признак; при несовпадении frontend не принимает результат. Отсутствие поля в ответе старого backend допускается.

Для объяснения фронтенд использует контракт:

```http
POST /api/v1/risk-calculations/{id}/explanations
```

Тело запроса пустое: backend должен брать данные из сохранённого расчёта текущей сессии. Ожидаемый JSON-ответ:

```json
{
  "calculation_id": "<ID расчёта>",
  "text": "Текст объяснения",
  "validation_ok": true,
  "sources": ["Источник фактов"]
}
```

### Готовность, валюты и восстановление метрик

`calculation_status` поддерживает `ready`, `estimate_possible`, `unavailable`. Статус `estimate_possible` разрешает запрос при `ready_for_calculation: false`, если отсутствуют только дюрация/выпуклость и доступны цена и НКД. Интерфейс предупреждает о возможном восстановлении через ML; успех не гарантирован. При отсутствии нового поля используется старый флаг. Недостающие цена, НКД, валюты и FX блокируют оценочный расчёт.

Валюта номинала `currency`, валюта цены `price_currency` и валюта НКД `accrued_int_currency` отображаются отдельно. Для старого backend без новых полей применяется валюта инструмента; явный `null` не заменяется другой валютой. Результаты `market_value` и `dv01` backend уже выражает в рублях, повторной конвертации нет. У результатов показаны `price_fx_rate`, `accrued_int_fx_rate`, соответствующие `*_fx_date` и `*_fx_source` (для RUB курс 1, дата и источник могут быть null). Контракт FX сверён с backend PR #11 (`d142417`).

`duration_estimate` и `convexity_estimate` сохраняются вместе с результатом: источник, версия модели, диапазон, необходимость проверки и ограничения. Ошибки расчёта сохраняют проверенные строки `details`: ISIN/ID инструмента, параметр, валюту и дату. Ошибка POST не создаёт частично успешный итог.

Причины недоступности ML отображаются отдельно от отсутствующих рыночных данных. Для `ml_unsupported_input`, `calculation_timeout`, `explanation_unverified` и `explanation_timeout` показаны отдельные сообщения. Факты подробного объяснения имеют подписи с единицами сдвига доходности и коэффициентами формулы.

### Стресс-сценарий на главной

Под блоком объяснения после расчёта появляется сценарий с ручным вводом и кнопками −/+. Стрелки ↑/↓ в поле меняют значение на 1 bp. Диапазон −200…+200 bp, дробные значения также допускаются. 100 bp — один процентный пункт. Только отдельная кнопка отправляет:

```http
POST /api/v1/risk-calculations/{id}/stress-scenarios
```

```json
{ "shift_bp": 100, "include_ml_analysis": false }
```

Используются ID и данные сохранённого расчёта текущей cookie-сессии. Отображается `total_change_rub` в RUB, с указанием сдвига, даты, приближённости и использования восстановленных метрик. Это изменение стоимости при выбранном сдвиге, не новая DV01. Дополнительный ML-анализ сценария не запрашивается. Ответ проверяется на соответствие ID, дате, сдвигу, позициям и сумме. Таймаут — 30 секунд. Изменение сдвига отменяет запрос и удаляет старый результат; изменение исходной сделки удаляет весь блок. В корзине стресс-сценария нет.

## Тестирование

Настроены Vitest, React Testing Library и jsdom.

Реализованы автоматические тесты:

- Валидация ISIN.
- Валидация количества облигаций.
- HTTP-клиент: GET и POST, отправка cookie, обработка HTTP-ответов и ошибок соединения.
- Проверка работоспособности тестового окружения React.

Запуск всех тестов:

```bash
npm run test
```

Тесты выполняются без необходимости запускать backend.
